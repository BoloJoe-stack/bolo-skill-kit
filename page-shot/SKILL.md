# 网页逐页整页截图（page-shot）

**目标**：拿到一个网页，把它按视觉上的"页"逐页截成**整页长图**（不需要用户手工滚动、不用手工点 tab）。

**适用范围**：任何"多 tab / 翻页 / 超长滚动"的网页。典型是**交互式 HTML 报告**——内含 4 个 tab 靠点击切换、每层内容远超一屏。

---

## 第〇步：拿到网页文件

用户给的可能是一个链接、一个附件、一个在线地址。先把它变成**本地文件或可直接打开的 URL**：

- **本地 `.html` 文件** → 直接进第一步
- **在线地址**（部署页 / 短链 / H5）→ 直接进第一步
- **挂在文档/云盘里的 HTML 附件** → 先定位附件、下载到本地（见「附录 A：来源是飞书」）

⚠️ 链接里**不一定直接是目标网页**——可能给的是外层文档，HTML 在另一个文档里，或者一篇文档里挂了多个 HTML。
**拿不准就问用户截哪个**，别猜。

下载后记下两样：**文件名**（做输出任务名用）和**文件所在目录**。

---

## 第一步：渲染

- **`file://` 常被浏览器自动化工具拦住** → 本地文件必须起一个临时静态服务再开：

  ```bash
  cd "<html 所在目录>" && python3 -m http.server 8765 --bind 127.0.0.1   # 后台运行
  ```

  再用 `http://127.0.0.1:8765/<对文件名做 percent-encode>` 打开。

  ⚠️ **中文文件名编码极易漏字 → 404**。稳妥做法：先取一次目录列表，把真实 href 拷来当 URL：

  ```bash
  curl -s http://127.0.0.1:8765/ | grep href
  ```

- **已在线的 URL** 直接用浏览器工具打开。

---

## 第二步：分析结构，决定怎么切页（自适应）

打开后先读页面结构，找"这里有几页"的证据：

| 证据 | 看什么 |
|---|---|
| **页数提示** | 标题/角标里的 `L1 / 4`、`1 / 4`、页码、分页圆点 |
| **切换控件** | tab 按钮、上一页/下一页、左右箭头、下拉选页、缩略图 |
| **内容高度** | 是否远超一屏（要整页长图，不是视口截图） |

**分支**：

- 有多页证据 **+** 切换控件 → **逐页截**：每页切过去，各做一张整页长图
- 只有一块超长内容、无切换 → **一张整页长图**
- **看到了页数提示却找不到切换控件**（比如只能点图翻页）→ 再找箭头/可点区域；仍不明就**停下来问用户要几张**

**切 tab 的注意**：用**可访问名**（按钮文字）定位，不要死记元素引用——切换后引用可能失效。

---

## 第三步：逐页整页长截图

1. **先建输出目录**。浏览器自动化的截图输出常默认落在**会话当前目录**，所以：
   - 目录必须**先存在**
   - 传路径时用**相对子路径**，不要传裸文件名

   ```bash
   mkdir -p "<输出根>/<任务名>"
   ```

2. 默认 **1x 整页 PNG**，文件命名 `NN_页面标题.png`：
   - `NN` = 顺序号
   - 页面标题取 tab/标题文字，**清掉文件系统非法字符**

3. 每一页的节奏：**切到该页 → 等内容稳定**（有懒加载图要等图）**→ 截图 → 切下一页**

4. **截完做互异性校验**：各张图应**互不相同且非空白**（例如用 PIL 缩小后算平均差 / 方差）。
   这是为了防"切页没生效，截出来全是同一页"——**这个问题肉眼翻图很难发现，必须机器判**。

---

## 第四步：收尾与汇报

- **停临时服务**：用任务管理机制停后台任务，**别用 `taskkill python` 之类的粗暴办法**（会误杀别的 python 进程）
- 关掉浏览器
- 清理可能落在会话当前目录的杂物
- **汇报**：截了几页、每张的路径与尺寸
- 默认 1x；用户要**打印/插图级** → 用附录 B 重截 2x

---

## 常见坑（都是实战踩出来的）

- **`file://` 被拦** → 一律走 `http(s)`
- **中文文件名 URL 编码漏字** → 照目录列表的 href 抄 URL，别自己编码
- **本地服务必须在 HTML 所在目录起**，否则 404
- **截图默认落在会话当前目录** → 先建目标子目录，路径用相对子路径
- **页面带固定 tab 头**时，每张整页图都会含头部 → **正常，不是 bug**
- **tab 按钮/图标 emoji 在终端显示乱码** = 控制台编码问题（GBK），**数据本身没坏**
- **找不到切页控件、或"要交互才看到其他页"但不知道点哪** → **停下来问用户**，别瞎截

## 附录 A：来源是飞书

HTML 挂在飞书文档/知识库里时，定位与下载：

```bash
# 1. 解析 wiki 节点，拿 obj_token / obj_type / title
lark-cli wiki +node-get --node-token <wiki链接或token>

# 2. 抓文档全文，在 content 里找 HTML 附件
lark-cli docs +fetch --doc <obj_token> --doc-format xml
#    形如：<source name="xxx.html" mime="text/html" size="64342" token="...">

# 3. 下载附件
lark-cli docs +media-download --token <source token> --output "<name>"
```

- 给的是任意飞书链接（wiki/docx/doc），**不一定直接含目标 HTML**——拿不准先用全文搜索按文件名/关键词命中再定
- 一篇文档里**有多个 HTML**、或用户点名了某个文件名 → 按文件名选；**不确定就问用户**
- 记下 `name`（做输出任务名）和 `token`

## 附录 B：打印级 2x 高清重截

默认 1x 够网页/存档用。要更高清时：

**首选**——在浏览器自动化里开一个 `deviceScaleFactor: 2` 的新页面再截整页（文本/矢量内容才能真正翻倍清晰）：

```js
async (page) => {
  const browser = page.context().browser();
  const ctx = await browser.newContext({
    deviceScaleFactor: 2,
    viewport: { width: 1280, height: 900 },
  });
  const p = await ctx.newPage();
  await p.goto('http://127.0.0.1:8765/<encoded>.html');
  await p.getByRole('button', { name: '<tab 名>' }).click();
  await p.screenshot({ path: '<输出目录>/2x_<页名>.png', fullPage: true });
  await ctx.close();
}
```

**退而求其次**（开不了新 context）：仍按 1x 截，再用 PIL `LANCZOS` 放大到目标宽度。
⚠️ 对**文字类**页面清晰度提升有限——**必须如实告诉用户**，别让人以为真变清晰了。
