# 项目收尾（project-update）

> 一条龙收尾一个项目：更新工作日志 / 项目状态 / README；有 git 仓库的再跑自检、敏感扫描、commit、push。

## 它解决什么

一次开发做完，真正花时间的往往不是写代码，而是**收尾**：补日志、更新状态、跑自检、确认没把不该提交的东西提交上去、写 commit、推上去。

这个 skill 把它做成一条流水线，**全程自动不问人**，只在真正该停的地方硬停。

## 最有价值的两处

### 一、仓库分四档，不是所有项目都该走全套

| 状态 | 做什么 |
|---|---|
| 有库 + 远端是自己的 | **全套**：文档 + 自检 + 敏感扫描 + commit + push |
| 有库 + 无远端 | 文档 + 自检 + 敏感扫描 + **commit，不 push** |
| 有库 + 远端是别人的 | **整个 skill 不适用**，告知后结束 |
| **没建库** | **只做文档 + 自检**，并注明"未建库" |

**没建库不是异常路径。** 很多项目压根不该建库，**补工作日志才是最有价值的那一半**——不要因为它没库就整个不干活。

同样地：**不要顺手 `git init` 帮人建库。** 建不建库是个要认真想的决定（私密还是公开、放哪个账号、`.gitignore` 怎么写），不属于收尾该干的事。

### 二、敏感扫描，以及那个"扫到自己"的坑

扫描规则**以各仓库自己的 `.gitignore` 为唯一事实源**，不另立白名单黑名单。只扫它漏掉的。

**真实踩过的坑**：某一轮扫描报工作日志命中 `ghp_` / `github_pat_`，翻了半天是**误报**——命中的是日志里这行：

> 敏感串扫描：`ghp_` / `github_pat_` / `sk-` / `AKIA` / 私钥 / `Bearer` —— **零命中**

**记录"我扫过哪些模式"的那句话，本身就是模式名的匹配源。**

**解法**：每条模式都必须带「**尾巴长度**」——真 token 是 `ghp_` + 36 位乱码；文档里提到时后面跟的是反引号/空格/斜杠，长度不够，自然不报。

```bash
git grep -n -I -E \
  "sk-[A-Za-z0-9]{20}|ghp_[A-Za-z0-9]{36}|github_pat_[A-Za-z0-9_]{60,}|AKIA[0-9A-Z]{16}|-----BEGIN [A-Z ]*PRIVATE KEY|Bearer [A-Za-z0-9_.-]{30}|password *="
```

配套第二条：**命中后先看尾巴**。前缀后面不是连续 token 字符的，判误报，用一行注明即可，**不硬停**。

## 硬停清单

命中即停，不自行决断：自检红 / 扫到疑似凭据 / `origin` 不是自己的仓库 / 需要 force push / 找不到工作日志文件 / 分支与远端分叉。

## 两条纪律

**自检要认项目既有方式，别新发明一套。** 先看项目里已经有什么（`Cargo.toml` / `package.json` / `Makefile` / 自带核对脚本），跑那个。**都没有就跳过，并在汇报里写明"无自检可跑"**——省掉这一句，读的人会默认你验过了。

**只推自己的库。** 项目目录下常常混着第三方仓库（vendor 的、clone 来的），它们有写权限但不是你的。**这是最容易犯、后果最重的一条。**

## 用法

```
"更新项目"    "更新一下项目"    "项目收尾"
```
