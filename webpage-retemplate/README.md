# 网页套版（webpage-retemplate）

> 拿一份已有网页的版式当模板，把另一份内容填进去。
> **版式照抄，内容全换——难点从来不在写页面，而在证明内容和原文一致。**

## 它解决什么

"照着这个页面的风格，把我们这份文档做成那样的页面"——这个需求看起来很直接，实际最容易出事的地方是**抄版过程中的文字失真**：

- 漏一个字（「的成员」变成「成员」）
- 顺手补一句原文没有的话（原文只有「可复用」，写成「可解释、可复用」）
- 数据编造（参考页有明细拆分，原文没有）

**这三种错，肉眼全看不出来。** 所以这个 skill 的核心不是写作指南，而是一套**机器核对管线**。

## 核心：三道核对

| 方向 | 查什么 |
|---|---|
| **正向** | 原文里的数字/人名/文献/断言句，页面上**有没有漏** |
| **反向** | 页面上的数字/文本块，原文里**找不找得到**（防杜撰） |
| **链接** | DOI / URL 双向比对，不多不少 |

配套两个可直接复制的脚本（`templates/`）：

| 文件 | 作用 |
|---|---|
| `page_check.py` | 真浏览器渲染 → 跑交互、抓控制台、逐档视口查横向溢出、出截图、落 `rendered.txt` |
| `fidelity_check.py` | 拿 `rendered.txt` 跟原文做正向 + 反向 + 链接比对 |

**用法**：复制到 `<任务>/_src/` 下，改写文件开头标注的「断言区」（那是每次要重写的部分），然后先跑 `page_check.py` 再跑 `fidelity_check.py`。

## 三条铁律

1. **只换内容，不换版式。** 设计令牌、组件结构、交互、响应式断点一律照抄
2. **只搬运，不创作。** 原文没有的数据、结论、案例，一个字都不编
3. **机器核对，不靠肉眼。**

## 几个最容易踩的坑

**必须以「渲染后的 DOM」为基准，不能拿静态 HTML。**
JS 运行期生成的内容（Tab 里的数据、动态渲染的表格）在静态 HTML 里核对**必然误报缺失**。

**核对脚本自己的假阳性要先排除**，否则你会去"修"根本没坏的东西：
- `<script>` 块里的内容**要计入**页面文本（动态数据在里面）
- 原文里的裸写 `DOI: 10.x` 没有 `http://`，链接正则要单独扫
- 归一化必须抹平各种全角/半角引号与书名号

**探针元素必须尺寸固定。** 测缩放系数时用固定尺寸的方块；用含长文本的块测高度，改缩放会改变可用宽度 → 换行行数变化 → 比值失真。

**Windows 下不要用 `shutil.move` 搬 git 仓库。** `.git/objects` 里的 loose object 带只读属性，`os.rename` 会失败，`shutil.move` 退化成「复制 + 删除」——结果目标处有完整一份、源处留残缺一份。**完整教训见 SKILL.md。**

## 适用 / 不适用

**适用**：参考页是单文件 HTML（视觉报告 / 学习页 / 落地页 / 长图），内容源是文档或表格，产出仍是单文件 HTML。

**不适用**：
- 只有「风格参考图」没有可读代码 → 那是设计任务
- 要改的是版式本身 → 那是改版
- 参考页是 React/Vue 工程 → 先判断能否降级成单文件，不能就别硬套
