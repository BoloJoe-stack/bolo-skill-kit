# 网页套版（webpage-retemplate）

依据既有网页的版式生成新页面，内容替换为另一来源。

**版式照抄，内容全换。** 技术难点不在页面生成，而在于**证明内容与原文一致**。

## 功能定位

"参照该页面的版式，将本文档制作为同形式的页面"——此类需求看似直接，实际风险集中于**版式复刻过程中的文字失真**：

- 文字遗漏（「的成员」被简写为「成员」）
- 补充原文不存在的内容（原文仅有「可复用」，写作「可解释、可复用」）
- 数据杜撰（参考页含明细拆分，而原文无对应数据）

上述三类错误**均无法通过人工目视发现**。因此本 skill 的核心不是写作规范，而是一套**机器核对管线**。

## 核对管线

| 方向 | 核对内容 |
|---|---|
| **正向** | 原文中的数字、名称、文献、断言句是否均出现在页面 |
| **反向** | 页面上的数字与文本块能否在原文中找到对应（防杜撰） |
| **链接** | DOI / URL 双向比对，不增不减 |

配套脚本位于 `templates/`：

| 文件 | 功能 |
|---|---|
| `page_check.py` | 真实浏览器渲染；执行交互、捕获控制台错误、逐档视口检查横向溢出、生成截图、输出 `rendered.txt` |
| `fidelity_check.py` | 以 `rendered.txt` 与原文比对，执行正向、反向与链接核对 |

**使用方式**：复制至 `<任务>/_src/`，修改文件开头标注的「断言区」（每次套版需重写的部分），依次执行 `page_check.py` 与 `fidelity_check.py`。

## 三项基本要求

1. **仅替换内容，不修改版式。** 设计令牌、组件结构、交互、响应式断点一律照抄
2. **仅搬运，不创作。** 原文不存在的数据、结论、案例不得编造
3. **以机器核对为准，不以目视判断。**

## 主要技术风险

**须以渲染后的 DOM 为基准，不得使用静态 HTML。**
JavaScript 运行期生成的内容（标签页数据、动态渲染表格）在静态 HTML 中核对**必然产生缺失误报**。

**须优先排除核对脚本自身的假阳性**，否则将修正并未损坏的内容：

- `<script>` 块中的内容**须计入**页面文本（动态数据位于其中）
- 原文中裸写的 `DOI: 10.x` 无 `http://` 前缀，链接正则须单独处理
- 归一化须抹平全角与半角的引号、书名号差异

**探针元素须尺寸固定。** 测量缩放系数时须使用固定尺寸元素；若以含长文本的块测量高度，缩放会改变可用宽度，导致换行行数变化，比值失真。

**Windows 环境下不得使用 `shutil.move` 迁移 git 仓库。** `.git/objects` 中的 loose object 带只读属性，`os.rename` 会失败，`shutil.move` 退化为「复制 + 删除」，导致目标位置完整、源位置残缺。**完整说明见 `SKILL.md`。**

## 适用范围

**适用**：参考页为单文件 HTML（视觉报告、学习页、落地页、长图），内容源为文档或表格，产出仍为单文件 HTML。

**不适用**：

- 仅有风格参考图、无可读代码 —— 属设计任务
- 需修改版式本身 —— 属改版任务
- 参考页为 React/Vue 工程 —— 须先评估能否降级为单文件；不能则不建议采用
