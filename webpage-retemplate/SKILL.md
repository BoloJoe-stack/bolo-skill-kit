# 网页套版

拿一份**已有的网页版式**当模板，把**另一份内容源**填进去。
版式照抄，内容全换——**难点从来不在写页面，而在证明内容和原文一致。**

## 适用 / 不适用

**适用**：参考页是**单文件 HTML**（视觉报告 / 学习页 / 落地页 / 长图），内容源是文档或表格，产出仍是单文件 HTML。

**不适用**：
- 只有「风格参考图」没有可读代码 → 那是设计任务，不是套版
- 要改的是版式本身 → 那是改版
- 参考页是 React/Vue 工程 → 先判断能否降级成单文件；**不能就别硬套**

## 三条铁律

1. **只换内容，不换版式。** 设计令牌、组件结构、交互、响应式断点一律照抄。
2. **只搬运，不创作。** 原文没有的数据、结论、案例，**一个字都不编**。
3. **机器核对，不靠肉眼。** 抄版最容易出「漏一个字」「顺手补一句」，**这两种错肉眼都看不出来**。

## 流程

### 0 · 摸清参考页

读参考页全文，列出：**设计令牌**（`:root` 里的色板/缩放系数）、**组件清单**、**章节骨架**、**交互 JS**。

### 1 · 拉内容源

把内容源落盘成 `_src/原始文档.md` —— **这份就是后面核对的唯一基准**，别在别处留副本。
来源是压缩包则先解到 `_src_zips/`，**别直接改原件**。

> 来源是飞书文档时，可以用 `lark-cli docs +fetch --doc-format markdown` 拉成 markdown。

### 2 · 澄清承重问题（**写代码之前**）

一次问齐，**别挤牙膏**。这类任务里**承重且推不出**的通常是：

- **引用/文献怎么处理**：正文保留、出处收到卡片底部小字，还是全文照录？
- **哪些区块做交互**：参考页有 Tab/折叠区，原文没有对应数据，做还是不做？
- **有没有东西明确不照搬**：参考页里的数据/案例若原文没有，必须问清「不搬」还是「编」（**答案永远是不搬**）

### 3 · 提取内容，产出提取稿

写 `_src/内容提取稿.md`：每个待上网页的文本块 + **它在原文的第几行**。

原文里没有、但你打算写进页面的**连接语/标题**，**单独标记出来**，别混在搬运内容里。

### 4 · 搭骨架 + 填入

先落版式骨架（CSS/组件照抄），再填内容。
大改动**用脚本做字符串级拼接**（保留 `<style>`/`<script>` 原样），**避免整文件重写引入转录误差**。

### 5 · 内容保真核对 ★ 核心

复制 `templates/` 下两个脚本到 `<任务>/_src/`，**改断言列表**（这是每次要重写的部分），然后：

```bash
python3 "_src/页面检查.py"    # 先渲染，产出 rendered.txt
python3 "_src/核对脚本.py"    # 再核对
```

**三道检查缺一不可**：

| 方向 | 查什么 |
|---|---|
| **正向** | 原文里的数字/人名/文献/关键句，页面上**有没有漏** |
| **反向** | 页面上的数字/文本块，原文里**找不找得到**（防杜撰） |
| **链接** | DOI / URL 双向比对，**不多不少** |

### 6 · BUG 检查

同两个脚本：控制台报错、未捕获异常、导航锚点命中、交互全跑一遍、**逐档视口查横向溢出**。

### 7 · 交付

- 源目录留一份**完整工作记录**（原文、提取稿、核对结果、脚本、截图）
- 中间产物一律进 `<任务>/_src/`，**不散落根目录**

## 陷阱清单（都是踩过的，按疼感排序）

### 核对相关

**1. 必须以「渲染后的 DOM」为基准，不能拿静态 HTML。**
JS 运行期生成的内容（Tab 里的数据、动态渲染的表格）在静态 HTML 里核对**必然误报缺失**。
先渲染落 `rendered.txt`，再拿它跟原文比。

**2. 只做正向核对会漏掉「杜撰」。**
必须加**反向扫描**：页面上的每个数字、每段文本块，拿去原文里找。
找不到的分两类——**可接受的连接语** vs **新增事实**，逐条人工过。

**3. 核对脚本自己的假阳性要先排除**，否则你会去"修"根本没坏的东西：
- `<script>` 块里的内容**要计入**页面文本（动态数据在里面）
- 原文里的裸写 `DOI: 10.x` 没有 `http://`，链接正则要**单独扫**
- 归一化必须抹平各种全角/半角引号与书名号，否则「《书名》」vs 斜体 会被判成不一致

**4. 探针元素必须尺寸固定。**
测缩放系数时用**固定尺寸的方块**；用含长文本的块测高度，改缩放会改变可用宽度 → 换行行数变化 → **比值失真**。

### 内容相关

**5. 改写过的句子最容易掉字。**
「的成员」「旅行」这种小词，改写时一漏一个。
**凡是动过措辞的句子，必须回到原文核对**——这条逮住过两次真实错误。

**6. 不要顺手补原文没有的话。**
最隐蔽的错误：写出「对需要『可解释、可复用』的场景，这一点尤其重要」——查了才知道原文只有「可复用」，没有「可解释」。
**它不会触发任何既有断言。**
写完新句子后**逐句回原文找依据，找不到就删**。

**7. 用户没给的数据绝不编。**
参考页里有典型用户故事、有明细权重拆分，原文没有 → **就是不做**，并跟用户说清。
真要做，那是"编数据"，**必须用户明确点头**。

### 版式相关

**8. 改字号/缩放后，响应式断点要跟着挪。**
用 `body { zoom }` 做整体缩放会折算布局视口，断点不同步就会出现「窗口还宽着、版式已塌成手机版」。
media query **不支持 `var()`**，得手工改。把缩放系数抽成 `:root` 变量，以后一句话就能调。

**9. 动 CSS 前先 grep 计数。**
删掉 HTML 区块后，对应的 CSS 会变死代码——**顺手清掉**。

**10. 元素截图里粘性导航重叠是假象，不是 BUG。**
拼接长元素时会把 sticky 导航重复合成。**用整页截图或状态断言确认，别去改代码。**

### 搬迁相关

**11. Windows 下不要用 `shutil.move` 搬 git 仓库。**
`.git/objects` 里的 loose object **带只读属性**，`os.rename` 会失败，
`shutil.move` 就退化成「复制 + 删除」——复制成功、删只读文件失败，
结果**目标处有完整一份、源处留残缺一份**。此时若误判目标是"半成品"删掉，源又缺了 `.git/HEAD`/`config`，**仓库就废了**。

**正确做法**：先递归 `os.chmod(p, stat.S_IWRITE)` 清只读属性，再 move；或直接重新 clone。
**判断半成品前务必先 `ls -la`**（不带 `-a` 看不到 `.git`，会误判）。

## 资产

`templates/` 下两个脚本，复制到 `<任务>/_src/` 后**改断言列表**：

| 文件 | 作用 |
|---|---|
| `page_check.py` | 真浏览器渲染 → 跑交互、抓控制台、查溢出、出截图、落 `rendered.txt` |
| `fidelity_check.py` | 拿 `rendered.txt` 跟 `_src/原始文档.md` 做**正向 + 反向 + 链接**比对 |

> 两个脚本都用**独立浏览器实例**，不走共享的浏览器自动化服务（那个有 profile 锁，多任务会撞车）。
> 依赖：`python3` + `playwright`。
