# 给文档条目找文献依据

**输入**：一份**待溯源的文档** + 条目号。
**做什么**：读该条目原文 → **先查已有文献库** → 自己造检索词在 Google Scholar 搜够 5 篇英文文献 → **停下给用户挑** → 挑完按固定格式写「信源记录」，并把本轮全部候选登记回文献库。

## 两条铁律

1. **每轮只做一条，出 5 篇就停，等用户指令，绝不自动进下一条。**
2. **搜之前先查文献库**——同一篇论文常能支撑多个条目，**别重复劳动**。

---

## 第 0 步：确认文档与项目

**先跟用户确认这次是哪个文档、哪个项目**（第一次用时尤其要问清楚），然后确立目录结构。

### 目录约定

| 项 | 值 |
|---|---|
| 项目根 | `<项目根>/` |
| 候选存放 | `<项目根>/文献/` |
| 定稿存放 | `<项目根>/信源记录/` |
| 总库 | `<项目根>/文献库/` |
| 文献库索引 | `<项目根>/文献库/索引.md` —— 所有搜过的文献总登记表 |
| 进度表 | `<项目根>/进度.md` |

首次使用时建齐 `文献/`、`信源记录/`、`文献库/` 三个子目录，并初始化 `索引.md` 和 `进度.md`。

### 其它固定参数

| 项 | 值 |
|---|---|
| 检索渠道 | **Google Scholar**（走浏览器自动化，不要用内置的网页搜索工具） |
| 文献语言 | 英文为主 |
| 每轮篇数 | **5 篇候选** |
| 摘要来源 | **只看 Scholar 给出的标题与摘要片段，不打开原文** |

读 `进度.md`（不存在则建）。用户要跑的那条**若已标记完成，先提醒**并问「重跑还是跳过」。

---

## 第 1 步：定位条目，提炼「问题原文」

读文档，按条目号定位到对应章节，提炼出**两句**：

- **命题**：该条目主张什么（从原文提炼，可摘关键句）
- **追问**：评审者/他人当时的质疑原话或大意

如果文档带批注，批注里通常有 `quote`（引文）和 `msg`（内容）两个字段——**可据此判断质疑落在哪句话上**。

> ⚠️ **以实际读到的为准，不要依赖记忆里的条目表。** 文档会变。

---

## 第 2 步：先查文献库

读 `文献库/索引.md`，用条目的关键词与命题去比对，找**可能匹配的已有文献**。

- **找到匹配** → 摆出来告诉用户「库里有 N 篇可能对得上」，问是：
  **直接复用** / **作为检索起点**（顺着它的引用或主题往下搜）/ **照常全新搜**
- **没找到** → 直接进第 3 步

> 库里标「备选」「弃用」的条目**同样要查**——它们本来就未失效，留着就是为了后面几条复用。

---

## 第 3 步：生成检索词并迭代

从条目原文提炼 **3–5 组**英文检索词，**覆盖三个角度**：

1. **学理命名**：该现象在学术上叫什么（如「主导动机」→ `"dominant motive"`）
2. **方法主线**：所属的成熟研究传统（如「动机细分」→ `"motivation-based segmentation"`）
3. **场景贴近**：本项目的行业/人群属性（如某种运动/消费品 → 对应的领域词）

### 检索式写法

```
https://scholar.google.com/scholar?hl=en&as_sdt=0%2C3&q=<URL编码的检索词>
```

**三条警告**：

- ⚠️ **不要用按日期排序**（`scisbd=1`）：泛化关键词 + 按日期排序会返回大量无关领域的新论文（实测某次泛化词的结果全被工程/医学论文占据）。**默认按相关度排序。**
- ⚠️ **多词短语加英文双引号**，否则会被拆成宽匹配。
- ⚠️ **当心一词多义**：同一个词在不同学科含义完全不同（如 `segmentation` 在市场细分之外还指图像分割）。**命中领域不对就立刻换词。**

**迭代规则**：某组检索词的前 10 条里**若超过半数属于不相关领域，判为废词**，立刻换下一组，并在候选文件里记下这次试错。

### 结果抓取

导航后用下面这段**一次取回全部结果行**的标题/作者年刊/摘要片段：

```js
() => {
  const rows = [...document.querySelectorAll('.gs_r.gs_or.gs_scl')];
  return rows.map((r, i) => {
    const t = r.querySelector('.gs_rt'), a = r.querySelector('.gs_a'),
          s = r.querySelector('.gs_rs'), c = r.querySelector('.gs_fl');
    return [i+1, t?.innerText||'', '|', a?.innerText||'', '|',
            (s?.innerText||'').slice(0,350), '|',
            (c?.innerText||'').replace(/\n/g,' ')].join(' ');
  }).join('\n\n');
}
```

补摘要片段时，**用精确标题短语再搜一次**，Scholar 会给出更长的摘要开头。

---

## 第 4 步：筛选凑够 5 篇

**按此优先级挑**：

1. **领域必须对**：优先市场营销、消费者行为、休闲/旅游、体育管理、心理学等**对口学科**。**不对口的领域一律不要**
2. **正规期刊优先**：排除预印本、水刊、非同行评议来源
3. **高被引优先**：同等条件下选被引次数高的
4. **场景贴近优先**：同领域内，优先人群属性与项目接近的

**凑不够 5 篇时**依次放宽，**并在文件里标注「⚠️ 降级收录」及原因**：

先降被引要求 → 再放宽年份 → 最后才含预印本/会议论文。

🔴 **不要静默降级。** 降了就写出来。

---

## 第 5 步：出 5 篇，**停下等挑选**

在对话里给出 5 篇，每篇包含：

**中文标题 + 英文标题 / 作者 / 年份 / 期刊 / 中文摘要简述 / 对本题的用处**

然后**停下**，明确说「等你挑」。

**不要自动写信源记录，不要自动进下一条。**

> **用户可能中途纠正检索方向**（例如指出「重点不是 X 而是 Y」）。这种情况**整轮重搜**，旧的一轮**不要删**——登记进文献库并标 `弃用`，将来别的条目可能用得上。

---

## 第 6 步：用户挑完后，写三个文件

### 6a. 候选文件 → `文献/第N题_<短名>.md`

按顺序记：

对应文档位置 / 对应条目 / 检索渠道 / 检索日期 / **全部检索式（含试错的 ✗ 与被采纳的 ✓、以及被整轮替换的旧轮次说明）** / 说明「只读标题与摘要」

然后 5 篇逐条展开（中文标题 + 英文标题、作者、年份、期刊、摘要简述、对本题的用处、链接），末尾「本轮小结」与「待办」。

### 6b. 信源记录 → `信源记录/第N题_<短名>.md`

**只用用户挑中的文献，重编为 1/2/3…**。

```markdown
# 第N题　<短名>

## 对应问题序号

**N**

（文档 §X.Y(Z) <条目名>）

## 问题原文

<命题：从文档原文提炼>

**<追问人>追问**：<质疑原话>

## 文献与对应结论

**1.** <全英文文献信息：作者 (年份). 标题. *期刊*. 出版社.>

　→ <该文献能解释的中文结论>

**2.** …（同上）

---

*检索渠道：Google Scholar　检索日期：YYYY-MM-DD*
```

**格式要点**：

- 「文献与对应结论」是**一条文献紧跟一条结论**，**不做成「文献列表 + 结论列表」两个分开的区块**
- 文献信息**全英文**；结论**全中文**
- 结论要写清「**这篇支撑了什么**」，即它如何回答该条目被质疑的点

### 6c. 登记回文献库 → `文献库/索引.md`

把**本轮全部候选**（含未被选中的、以及被替换的旧轮次）追加进索引表：

| # | 英文标题 | 中文标题 | 作者 | 年份 | 期刊 | 出自 | 状态 | 关键词 |

- `#` **沿用全库连续编号，不按题重置**
- **状态**：`选中` = 已写入信源记录 ｜ `备选` = 该轮候选但未被选中 ｜ `弃用` = 该轮被整轮替换，但**保留备查**
- **关键词**：填便于日后跨题检索的词（学理术语、方法名、场景词）
- 完整信息不重复写，**指向 `../文献/第N题_*.md`**

---

## 第 7 步：回写进度

更新 `进度.md`：

```markdown
| 题号 | 条目标题 | 状态 | 文献数 | 日期 | 备注 |
|---|---|---|---|---|---|
| 2 | <条目标题> | ✅ 已交付 | 3 | 2026-09-10 | 候选 5 篇存 文献/ |
```

---

## 收尾

清理抓取过程落在当前目录的产物（快照/日志），**别留在项目里**。

然后**停下**，等用户说下一条。
