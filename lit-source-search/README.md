# 给文档条目找文献依据（lit-source-search）

> 给文档里那些"有结论、缺依据"的条目找英文学术文献支撑。
> **每轮只做一条、出 5 篇候选就停下等你挑。**

## 它解决什么

写报告时经常要面对这种局面：**结论已经写出来了，但拿不出文献依据**，一被追问就站不住。

这个 skill 把"补文献依据"变成一条可重复的流水线。它最特别的地方不是检索技巧，而是**人机协作的节奏**——

## 两条铁律

1. **每轮只做一条，出 5 篇就停，等用户指令，绝不自动进下一条。**
2. **搜之前先查文献库**——同一篇论文常能支撑多个条目，别重复劳动。

第 1 条是关键。**不让 AI 一口气塞几十篇文献给你**——那样你既看不完，也没法逐条判断哪篇真的对得上。5 篇正好是"一次能认真读完并做出判断"的量。

## 三条检索纪律

从条目原文提炼 **3–5 组**英文检索词，覆盖三个角度：

1. **学理命名**——该现象在学术上叫什么
2. **方法主线**——所属的成熟研究传统
3. **场景贴近**——本项目的行业/人群属性

三条警告（都是实测的）：

- ⚠️ **不要按日期排序。** 泛化关键词 + 按日期排序会返回大量无关领域的新论文（实测某次泛化词的结果全被工程/医学论文占据）
- ⚠️ **多词短语加英文双引号**，否则会被拆成宽匹配
- ⚠️ **当心一词多义。** 同一个词在不同学科含义完全不同（如 `segmentation` 在市场细分之外还指图像分割）。**命中领域不对就立刻换词**

**迭代规则**：某组检索词的前 10 条里若超过半数属于不相关领域，判为废词，立刻换下一组，并把这次试错记下来。

## 筛选纪律

按优先级挑：**领域必须对口 → 正规期刊优先 → 高被引优先 → 场景贴近优先**。

**凑不够 5 篇时**依次放宽（先降被引要求 → 再放宽年份 → 最后才含预印本），**并在文件里标注「降级收录」及原因**。

🔴 **不要静默降级。** 降了就写出来。

## 产出

**三个文件**，各有用处：

| 文件 | 内容 |
|---|---|
| `文献/第N题_*.md` | 本轮**全部**候选 + 全部检索式（含试错的 ✗ 与被采纳的 ✓） |
| `信源记录/第N题_*.md` | **只用挑中的文献**，一条文献紧跟一条结论 |
| `文献库/索引.md` | 全库总登记表，编号连续不按题重置，标 `选中`/`备选`/`弃用` |

**「一条文献紧跟一条结论」**是格式要点——不做成"文献列表 + 结论列表"两个分开的区块。文献信息全英文，结论全中文。

## 用法

```
"搜文献"   "找文献依据"   "查信源"   "文献溯源"   "给第 N 题找文献"
```

首次使用时 skill 会先问清楚是哪个文档、哪个项目，然后建立目录结构。
