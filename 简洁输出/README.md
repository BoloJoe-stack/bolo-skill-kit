# 简洁输出

> 让 AI 回复更短、结论先行，技术事实一个不丢。

## 它解决什么

AI 助手的回复里，**壳**（客套、过程叙述、结尾复述）占比很高，而且是**双重成本**：一次是生成它的 token，一次是读它的时间。

这个 skill 就是删壳的规则集。但它和"请简洁一点"那种提示词的关键区别是——**它同时给出了一份"不许省略"的清单**，并规定了什么时候必须放弃简短。

## 效果边界（实测，不是宣称）

做过 A/B 对照测试。同一任务，一组加载本 skill 一组不加载，比较输出长度，并委派独立代理核查信息是否遗漏：

| 任务类型 | 输出篇幅 | 信息完整性 |
|---|---|---|
| 撰写文档、解释问题 | 减少约 **50%** | 基本无损失 |
| 代码审查、问题排查 | 减少 **34%–45%** | ⚠️ **遗漏 10–14 项发现** |

**结论：用于写文档、解释问题；不推荐单独用于代码审查和问题排查。**

压缩比由**散文与代码块的比例**决定，不由任务大小决定——代码块要逐字保留，那是动不了的"货"。

### 为什么把这个结论写进来

因为**一个带失效边界的提示词，比一个只讲好处的提示词有用**。

我们修改过一版专门针对"少报发现"的问题（新增了"完整性优先"条款），实测**效果只有一半**：模型会声明"我已完整报告"，但实际仍然存在遗漏。所以这条边界是真的，不是保守。

## 结构

规则分四层，**冲突时按这个顺序**：

1. **「什么时候必须破戒」** —— 最高。安全警告、不可逆操作、要落盘的东西、反问用户、报失败、不确定的断言、用户明确要推导……这些场景全部切回完整句子
2. **三条硬约束** —— 只报要用的数据 / 状态字≠结果 / 说"查过了"必须写清查到哪一步
3. **规则 1–7** —— 结论先行、删壳不删信息、不报过程、短词不造词、货要逐字给、语言跟随用户、不表演
4. **发送前自检**

## 用法

```
/简洁        /话少        "简洁点"      "少说废话"
"短一点"     "别啰嗦"      "省点token"   "说重点"
```

开启后整个会话持续生效，直到说「恢复正常」「关掉简洁输出」「完整说」。

## 注意

- 这是**中文版**。原版是英文的，它的核心判据建立在英语语法上（省冠词），对中文不适用——中文要删的是**整句的壳**，不是单个助词
- 「的」「了」不必刻意抠。多数时候它们省不了几个字，却在"动宾歧义"和"描述 vs 分类"两种场景下会改意思
- 「不能删」那张表保护的是**功能词**（或者、可能、至少、显著），**它保护不了"我发现了什么"**——这正是它在审查类任务上失效的原因
