# 简洁输出

压缩 AI 助手的回复篇幅，结论先行，技术事实不丢失。

## 功能定位

AI 助手的回复中，"壳"（客套语、过程叙述、结尾复述）占比较高，且成本是双重的：一次是生成其所耗的 token，一次是阅读其所耗的时间。

本 skill 为删减此类表达的规则集。与"请简洁一点"一类表述的关键差异在于：它**同时给出不可省略内容的清单**，并明确规定在何种情形下必须放弃简短。

## 实测边界

已进行 A/B 对照测试。同一任务分组执行，对照组不加载本规范，实验组加载；比较输出长度，并由独立代理核查信息遗漏情况。结果如下：

| 任务类型 | 输出篇幅 | 信息完整性 |
|---|---|---|
| 撰写文档、解释问题 | 减少约 **50%** | 基本无损失 |
| 代码审查、问题排查 | 减少 **34%–45%** | 遗漏 10–14 项发现 |

**适用建议：用于撰写文档、解释问题；不建议单独用于代码审查与问题排查。**

压缩比由**散文与代码块的比例**决定，与任务规模无关。代码块须逐字保留，属不可压缩内容。

### 边界数据的来源

规范中收录失效边界，而非仅陈述收益。

针对"漏报发现"问题曾进行修订（新增完整性优先条款），实测结果为**部分有效**：模型会声明已完整报告，但实际仍存在遗漏。因此该边界经过实测确认，非保守估计。

## 规则结构

规则分四层，冲突时按以下顺序适用：

1. **例外情形（最高优先级）** —— 安全警告、不可逆操作、需落盘的产物、反问用户、报告失败、未经证实的断言、用户明确要求推导等，均须改用完整句式
2. **三条硬性约束** —— 仅报必要数据；状态标识不等于结果；说明核查范围
3. **规则 1–7** —— 结论先行、删壳不删信息、不叙述过程、用词简短但不造词、原文逐字保留、语言跟随用户、不刻意表演
4. **发送前自检**

## 触发方式

```
"/简洁"  "/话少"  "简洁点"  "少说废话"
"短一点"  "别啰嗦"  "省点token"  "说重点"
```

启用后于整个会话持续生效，直至用户要求恢复正常输出。

## 注意事项

- 本 skill 为**中文版本**。原版基于英语设计，其核心判据（省略冠词）不适用于中文。中文需删减的是**整句层面的套话**，而非单个虚词
- 「的」「了」不必刻意删减。此类虚词通常节省有限，但在"动宾歧义"与"描述性 / 分类性"两类情形下会影响语义
- 不可删减清单保护的是**功能词**（或者、可能、至少、显著等），**不覆盖"已发现的结论"**。这是其在审查类任务上失效的根本原因
