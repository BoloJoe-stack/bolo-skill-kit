# 全自动模式（autonomous-mode）

把"停下来问"从**默认动作**降级为**例外动作**，用一份即时文档把自决的成本补回来。

## 功能定位

面向 Claude Code 及兼容 AI 编码助手的一段行为规范（纯文本，零依赖、零执行、零联网）。

它解决的问题不是"AI 做得不够多"，而是**默认行为里询问成本过高**：一个多步任务中，实现细节、参数取值、脚本写法、口径措辞若逐项请示，使用者会退化为审批通道，而其中绝大多数问题本不需要人回答。

规范把授权前移，同时以两样东西兜住风险：

- **一份即时的《自决记录》**——每个自决当场落档，写明候选、优劣、依据、结果、可逆性与回改路径。事后补记不算数。
- **一条硬的判据线**——授权不是无限授权，四类情形仍然必须停。

## 规则结构

| 层 | 内容 |
|---|---|
| 触发与有效期 | 说「全自动模式」生效；**只对当前任务有效**，收尾即退出，不跨会话继承 |
| 六条规则 | 方案是骨架、纠结不许停、只有四类停下问、测试必须外部化、自决即时落档、收尾交一份文档 |
| 判定线 | 红：方案级大改动 / 量产跑批 / 对外动作 / 破坏性操作；绿：对照实验、参数与提示词调整、抽样与清洗、脚本重构、自写口径的改动 |
| 边界与安全 | 累积漂移对账、回改闭环、凭据边界、标注义务、硬停项挂起 |
| 失效模式表 | 逐条列出本模式自身可能的失败方式与对应补偿 |

### 四类必须停下问

1. **方案级大改动**——管线顺序、换模型、目标人群或样本量、验收口径的实质变化、评估基线换源
2. **量产跑批**——产数据的正式批
3. **对外动作**——写协作文档、发消息、推代码仓库、发布
4. **破坏性操作**——删数据、覆盖历史留档

判据只有一条：**是不是这四类**。"会改变最终结果"**不是**停的理由——抽样、清洗、口径、试算都会改数字，它们全在自决栏里。这一条是规范里最容易被用错的地方，故单列澄清。

## 设计依据

### 一、为什么必须"测试外部化"

自验不是验证。**自己查自己会稳定地漏掉"我以为我知道但其实不知道"的那一类错**——断言盲区会原样继承。

因此规范把"派独立复核子代理"写成**默认授权动作**：遇到要验证的情形自行派出，无需逐次请示。任务书有两条硬要求：**必须写死只读**（否则复核代理会改动它正在核对的工作树，还回一个"已核对"的结论），以及**明确要它找"给了错信息"**而不只是"信息不够"。

> 实测：独立复核最值钱的产出是**抓"给了错信息"**（判错、配错、与原文矛盾、引用被改写），而非"信息不够"。两轮复核共 14 条，绝大多数属这一类。

### 二、为什么"派完就结束回合"

子代理在**父回合进行中**完成，会导致回传丢失。实测三次均如此。规范因此要求：派完优先结束回合；确需连续作业时先记下 agent id，回来用转录兜底。

### 三、"方向偏"是主要风险

细节全对、整体走歪，是授权式工作最典型的失败。补偿有两条，缺一不可：

- 每条决策强制写**可逆性**与**回改路径**，不可逆的立刻降级为"停下问"
- 每完成一个阶段、或每 5 条自决（先到者），**回方案对一次账**——"方案里还有哪几件事没做？现在做的是否已超出方案范围？"

单条决策都合规，不等于整体没跑偏。

## 实测

一项数据侧任务上按本规范运行，收尾《自决记录》记载：

| 项 | 数字 |
|---|---|
| 自决 | 9 条 |
| 测试 | 8 个 |
| 停下问 | 2 次 |
| 因属硬停而挂起 | 1 项 |
| 独立复核抓出"给了错信息" | 4 条，全部更正 |

## 触发方式

说「**全自动模式**」启用。退出：任务收尾自动退出，或说「退出全自动 / 停下」。

**不触发**：用户要求逐项确认时、纯问答、一次性能做完的小改。

## 注意事项

- **适用边界**：本规范降低的是**询问成本**，不降低**验证成本**。派独立复核、写即时记录这两项开销比默认模式更高——省下来的是人被打断的次数，不是总工作量。
- **模式不静默延续**：只对当前任务有效，收尾即退出，不跨会话继承；任务中断后恢复，先读最近一份《自决记录》再往下做。
- **《自决记录》只增不改**：已存在就续写，绝不覆盖；推翻旧决策时追加"修订"。

## 明确不做的

- ❌ 不做无限授权：四类硬停不可自决
- ❌ 不跨会话继承、不静默延续
- ❌ 不用文档替代证据（结果字段必须贴实际数字或命令输出）
- ❌ 不做二阶复核（代理的结论不再派代理去验，靠回原文自验兜底）
- ❌ 不因本模式获得任何对外发布授权
