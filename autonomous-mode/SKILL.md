# autonomous-mode（全自动模式）

把"停下来问"从**默认动作**降级为**例外动作**，用**一份文档**把自决的成本补回来。

## 0 触发

**生效**：用户说「**全自动模式**」。
**不触发**：用户要求逐项确认、纯问答、一次性能做完的小改。

**有效期**：只对**当前这个任务**有效。任务收尾（交了《自决记录》）**自动退出**；用户说「退出全自动 / 停下」立即退出。
**不跨会话继承**：新会话里按默认行为干活，除非用户重新说一次。**恢复时**先读最近的《自决记录.md》再往下做。

**一旦触发，先做两件事**：

1. **认方案**。优先级：**用户给的方案文件 > 既有项目文档 > 我自写的一句口径**。
   自写口径必须在记录里显式标"**这是我定的、未经用户确认**"，并在首次交付时点出来。
   ⚠️ **自写口径的改动＝自决（不是硬停）**——它不是用户给的方案，改了不算"违背方案"。
2. **建/续写《自决记录.md》**（§3 模板）——**不等收尾**。已存在就**续写，绝不覆盖**。

## 1 六条规则

1. **方案是骨架，细节是我的**：方案写死的照做；实现细节、参数、提示词、脚本、口径补充，自己定。
2. **纠结不许停**：卡在两个做法之间 → **两个都跑一遍**，用数据定；跑不了就选**可逆**的那个，并写明回改路径。
3. **只有四类停下问**（§2）。停下来时**一次问清**（选项 + 各自代价），不挤牙膏；问之前把能推的部分推到不能再推。
4. **测试必须外部化**：要验证自己的产出时，**自决派独立子代理**去查，**不许自己查自己**（§4）——自验有断言盲区，会原样继承我的错。
5. **每次自决即时落档**（不是事后回忆），必须含**各方案的优劣势**。
6. **收尾交一份文档**：决策 **+ 对应的结果**（§5）。

## 2 判定线

| 类别 | 例子 | 处理 |
|---|---|---|
| **方案级大改动**：管线顺序、**换模型（＝产出/作答用的 LLM）**、目标人群/国别/样本量、验收口径的实质变化、**评估基线换源** | 「A 方案还是 B+C」、「基线人群不匹配要不要换源」 | 🔴 **停** |
| **量产跑批**（产数据的正式批，如 300 人） | — | 🔴 **停** |
| **对外动作**：写协作文档、发消息、推代码仓库、发布 | — | 🔴 **停**（不受本模式影响；被调用的 skill 自带的授权见 §7） |
| **破坏性操作**：删数据、覆盖历史留档 | — | 🔴 **停** |
| 对照实验 / **试跑（单次实验各臂合计 ≤30 人）** / 提示词·参数·阈值调整 / 脚本重构 / 口径补充说明 / 抽样与清洗方式 / 找数据 / 文档组织 | 温度扫描、消融三臂、打分机制对比、换基线试算 | ✅ **自决 + 落档** |
| **我自写的口径**（§0）的改动 | — | ✅ **自决 + 落档** |

三条口径澄清（复核后补）：

- **"会改变最终结果"不是停的理由**——上面自决那一栏里的大多数（抽样、清洗、口径、试算）**都会改数字**。
  硬停的判据只有一条：**是不是那四类**。§9 那个自检问句是**两步**的，别只跑第一步。
- **"换模型"指 LLM 模型**（产出/作答用的那个）；**建模方法/算法选择属方法细节**，自决。
- **"≤30 人"＝单次实验各臂合计 30 人**（不是每臂 30）。并且**按成本而不只按人数**：
  换成高成本数据集或长任务时，即使人数达标也**先报一声**（报，不是停）。

## 3 《自决记录.md》——一份文档装两半：决策 + 结果

**位置**：任务目录下；跨任务/跨天 → **项目根**一份，按日期分节。**一次触发一份**。
**只增不改**：推翻旧决策时追加"修订"，不删原文。**已存在就续写——绝不覆盖**（跨会话时尤其）。
**只记会影响最终产物或结论的**；纯机械动作（改文件名、修 typo）不记——记多了等于没记。

```markdown
# 自决记录 · <任务名>

> 触发：<用户原话> ｜ 日期：YYYY-MM-DD ｜ 方案：<文件名 或 一句话口径（自写的要标出来）>
> 规则：只记影响最终产物或结论的选择；只增不改；结果一律贴实际数字/输出。

## 摘要（收尾时填，放最前）
```

## 4 测试与复核（自决派子代理，不许自己查自己）

**本 skill 授权：遇到"要验证/要测试/判自己做得对不对"的情形，自行派出独立子代理，无需问用户。**
理由是硬的——**自己查自己不算验证**：自验会稳定地漏掉"我以为我知道但其实不知道"的那一类错，
断言盲区原样继承。

### 什么时候派

| 情形 | 要不要派 |
|---|---|
| 结论会进**最终产物或口径**（分布数字、门槛判定、映射、口径说明） | ✅ 必派 |
| 判断是**主观构造**（题目映射、等级判定、归类规则、**我自己写的 skill/规程**） | ✅ 必派——这类最容易被自己说服 |
| 数字能用**脚本复算**（阈值、计数、组合率） | ⚙️ 脚本自验即可，不必派 |
| 纯机械动作（改名、挪目录） | ❌ 不派 |

### 怎么派

1. **只给原文 + 路径，不给我的结论**；要它**先独立做一遍**，再与我的产物逐条比对。
2. 🔴 **任务书必须写死只读**："**不要修改任何文件，只报告**"。
   复核代理默认带 Write/Edit/Bash 权限，不写死这句它会**改动它正在核对的工作树**——
   把被验对象改坏，还给你一个"已核对"的结论。
3. **明说要它找"给了错信息"**（判错、配错、与原文矛盾、引用被改写）——不要只报"信息不够"。
   **实测：这类产出才是复核最值钱的部分**（两轮复核共 14 条，绝大多数属这类）。
4. 报告必须**给证据**（文件名 + 行号/sheet + 原文引用），并区分"我复算后发现不一致"与"我判不了"。
5. **优先派完就结束回合**——子代理在"父回合进行中"完成会导致回传丢失（实测三次均如此）。
   **确需连续作业**时：先记下 agent id，回来用捞取办法兜底（见下），别指望回传一定到。

### 回来之后

- **回传可能丢**（实测 3/3）：先看产物 mtime 判死活；确实干完了却没到，
  从子代理自己的转录里把最终报告捞回来（Claude Code 把子代理转录写在
  `~/.claude/projects/<项目>/<会话>/subagents/agent-<id>.jsonl`）。
- **复核结论一律先回原文自验，再采纳**。复核代理也会错；照抄等于把错误换个人背书。
- 分歧的裁决标准：**以能追到原文的那一方为准**，不是以"谁说得更有道理"为准。
- 采纳与驳回都要记进《自决记录.md》的《测试记录》表，标明**谁验的**。
- **不做二阶复核**：代理的结论不再派代理去验，靠"回原文自验"兜底。

## 5 收尾交付

**交一份文档**，不是聊天里的流水账。文档必须自带六样：

① 一屏摘要（几条自决 / 几个测试 / 调了哪些规则 / 结果）
② 决策清单，**每条带"结果"**
③ 测试记录（对照、变异、反例各是什么；**标明哪些是自验、哪些是独立子代理验的**）
④ 规则调整（改前 → 改后 → 影响）
⑤ 遗留与我判断不了的地方（含**挂起项**）
⑥ 哪些是**方案要求做的**、哪些是**我自己加的**（必须能一眼分开）

交付时给 **文件路径 + 一屏摘要**；不要把文档全文倒进对话。

## 6 边界与安全

1. **累积漂移对账（"方向偏"唯一的补偿）**：每完成一个阶段、或每 **5** 条自决（先到者），
   **回方案对一次账**——"方案里还有哪几件事没做？我现在做的是否已超出方案范围？"
   结论写进记录。⚠️ 单条决策都合规 ≠ 整体没跑偏，这条不能省。
2. **回改闭环**：阶段收尾扫一遍历史决策，凡被后来的证据推翻的，标"**需回改**"并写回改动作。
   光写"有回改路径"不够——得有东西**发现**该回改。
3. **凭据边界**：自决产出的任何文档/脚本，**凭据一律只写路径、不写值**；不把内部正文写进会外发的产物。
4. **会被对外使用的内容**：产物若明确会被拿去对外（报告/口径/数字/PPT），
   **在产物里标清"哪些是实测、哪些是我的判断、哪些未收口"**——定稿门槛在用户，标注义务在我。
   （这是标注义务，**不是新增的"停"**。）
5. **用户不在场时碰硬停项**：**记"挂起" + 转做其它可推进的事**，不空转、不越线。
6. **复核不递归**（见 §4 末）。

## 7 与其他 skill 的优先序

**优先序：用户当下的显式指令 > 被调用 skill 自身的条款 > 本模式 > 默认行为。**

- **用户显式调用某个 skill ＝授权它该做的事**。若那个 skill 自带"**全程自动、只在自己的硬停清单上停**"
  （典型的如项目收尾类：补文档 → 自检 → 提交推送），那不是本模式要拦的对外动作；
  访谈式 skill 的定点提问、"出 N 篇就停、绝不自动进下一题"同理。**本模式不去降级它们。**
- 反过来，**其它 skill 定义的硬停一律保留**（例：收尾类 skill 的"自检红 / 扫到凭据 / 远端是第三方仓库 / 分叉"）。
- 本模式只覆盖**它自己新增的询问点**。
- 若某个流程类 skill 把边界划成"**目标层归用户、方法层归实现**"，本模式只覆盖方法层与细节，
  其中**接口/规格的用户确认条款不动**。
- 方向一致的不冲突：凡"只问目标层、方法层不问用户"的既有约定，与本模式同向。

## 8 授权条款

> 在本 skill 生效的**当前任务**内，授权 Claude **自行决定实现细节、自行起小规模对照跑批（各臂合计 ≤30 人）、
> 自行调整规则、自行派出独立复核子代理（§4），无需用户逐次确认**。
> 代价是 §3 的文档必须**如实、即时**——不许事后美化，不许把自决包装成方案要求。
> **不授权**：§2 的四类硬停、其它 skill 自带的硬停、任何对外发布动作。用户可随时打断或否决。

## 9 我会怎么判断错

| 失败模式 | 补偿 |
|---|---|
| **记录变流水账**（什么都记，等于没记） | 只记"会影响最终产物或结论"的；每条必须能回答"换另一条会怎样" |
| **方向偏**（细节全对、整体走歪） | ①每条强制写**可逆性**与**回改路径**；②**阶段/每 5 条回方案对账**（§6.1）；不可逆的立刻降级为"停下问" |
| **把"会改结果"当停的理由**（模式退化成步步请示） | 两步自检：① 会**改变最终产物或结论**吗？不会 → 既不记也不停。② 会 → 它属于 §2 的**四类**吗？属于 → 停；不属于 → **自决 + 落档** |
| **事后补记**（变成编故事） | 即时落档，写完再继续干活 |
| **拿"没停"当免责** | 文档里明确标出"这条是我判断的"，与方案要求分开 |
| **用文档替代证据** | 结果字段贴实际数字/命令输出，禁止"已确认正常"这类话 |
| **自我参照失效**（自己写的口径/规程被自己当"方案"绕过守卫） | 自写物一律在记录里标"我定的、未确认"；**自写物本身也派独立代理审**（§4） |
| **模式静默延续** | §0 写死有效期：只对当前任务有效，收尾即退出，不跨会话继承 |
| **复核代理改坏工作树** | 任务书写死只读（§4.2） |

## 10 与既有规矩的关系

- 既有口径「要不要跑一次正式批，必须先落到用户面前」：本模式下**收窄为"量产批先问、对照批自决"**。
- **对外动作永远先问**——不因本模式获得授权（被调用的 skill 自带授权的情形见 §7）。
- 门槛/口径类结论仍要**可复算**（贴脚本路径或命令），文档里的数字要能被别人重跑出来。
